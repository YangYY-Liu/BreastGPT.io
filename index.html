Real breast oncology is not a single classification call — it is a patient-level clinical trajectory through screening → diagnosis → treatment planning, where each stage demands different modalities, reasoning style, and clinical vocabulary. We present BreastGPT, a unified multimodal agent system in which a router repeatedly reads the accumulated trajectory, selects the next stage-agent, and appends each structured output until a care plan is reached.

The agent is trained on BreastStage, a workflow-aligned instruction corpus of 1.86M pairs curated from 17 sub-datasets across 5 imaging modalities and 136 task templates. Its held-out split, BreastStage-Bench, evaluates how well an agent can reason across the full breast cancer care continuum — not just on isolated tasks.

Under the hood, BreastGPT pairs a dual-branch visual encoder with concept-preserving token compression to bridge the scale gap between standard radiology and gigapixel pathology — letting the same agent see a 224×224 BUS frame and a 100k×100k whole-slide image at the same downstream cost. On BreastStage-Bench it reaches 75.66% closed-ended accuracy and 89.92% open-ended score, outperforming proprietary frontier agents (GPT-5.4, Claude-opus-4-6, Gemini-3.1-Pro) and medical-specific VLMs alike.

1

Stage-aware agent orchestration

Three role-conditioned sub-agents (Screening / Diagnosis / Treatment) share one backbone and one weights checkpoint — selected by a stage-aware system prompt rather than separate task-specific heads.

2

Modality-aware visual routing

A resolution gating module routes each input to either the Standard branch (CT / MRI / BUS / Mammography) or the GigaPixel branch (WSI) — a tool-use pattern wired into the encoder itself.

3

Concept-preserving compression

A training-free concept-based token selector distills tens-of-thousands of patch features down to k = 128 tokens — keeping the agent fast (33× speed-up) without dropping clinically salient evidence.

02 · Agent System

Three agents, one workflow.

BreastGPT operates as a clinical agent system. A lightweight workflow router reads the patient context, dispatches the case to the correct stage-specialist agent, and aggregates evidence end-to-end — mirroring how a real breast oncology team hands a patient through screening, diagnosis, and treatment planning.

⚙️

Workflow Orchestrator

All three agents share one Qwen3-VL-8B backbone and one weights checkpoint. The orchestrator emits a stage-conditioned system prompt that switches the agent's persona, vocabulary, and target output schema — no task-specific heads, no separate models. This keeps deployment cheap (one GPU, one model) while preserving stage-specific clinical reasoning.

03 · Training Substrate

Teaching the agent the full clinical workflow.

To grow stage-specialist behavior under one backbone, the agent is trained on BreastStage — ≈662K unique 2D/3D images, 606K bounding-box / mask annotations, and 1.86M instruction-following pairs. The pair distribution (57.9% screening · 36.7% diagnosis · 5.4% treatment) deliberately tracks the real-world prevalence of cases at each handoff point of the 筛-诊-治 pipeline.

04 · Agent Internals

Inside the agent: perception, routing, compression.

Each sub-agent sees the world through a shared dual-branch perception stack. A modality-aware resolution gate works like a built-in tool router: standard radiology flows into a ViT Standard Branch, gigapixel WSIs into a specialized GigaPixel Branch (frozen CONCHv1.5 → trainable LongNet → universal concept-based token selector → LLM).

Stage-Aware Role Prompting

The orchestrator emits one of three system prompts (筛 / 诊 / 治) that switch the agent's clinical persona — its vocabulary, reasoning chain, and target output schema — without any task-specific head or LoRA swap.

Modality-Aware Visual Router

A resolution gate inspects every image and dispatches it to either the Standard Branch (Qwen3-VL ViT, for CT / MRI / BUS / Mammography) or the GigaPixel Branch (CONCHv1.5 + LongNet, for WSIs at 20×). Functionally, it's a tool router baked into perception.

Concept-Based Token Selector

A training-free coverage maximizer distills ViT or WSI features into exactly k = 128 tokens, jointly maximizing text–vision coverage (query relevance) and vision–vision coverage (visual representativeness) — the agent's working memory under a fixed budget.

Two-Stage Capability Bootstrap

Stage 1 warms up the perception front-end with the LLM frozen — aligning ViT and CONCH+LongNet with the agent's token space. Stage 2 fine-tunes end-to-end across every modality and every task format so the three sub-agents emerge from one training run.
